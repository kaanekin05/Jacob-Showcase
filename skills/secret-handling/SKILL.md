# Secret handling

Keep a secret out of the transcript, memory, and the repo. Move the value by clipboard or file. Report only its length, a match result, or its location.

- Never dump the whole environment (`env`, `printenv`, `set`, `export -p`) into the transcript. A session env var such as `CLAUDE_CODE_MESSAGING_TOKEN` prints its value. To check that a variable is set, print only its name and length, for example `env | cut -d= -f1 | grep -x NAME` or `[ -n "${NAME:-}" ] && echo set`. If a value already printed in chat, say so in one line and recommend rotating it if it is durable.
- Generate into the clipboard, never to stdout. Run `scripts/key-to-clipboard.sh [length]` (macOS). It prints the length only.
- Never write a secret to memory, the vault, a notes file, or a repo file unless the user names that file. Say in one line that you skipped it.
- The memsearch plugin records session text into `.memsearch/memory/*.md`, and that folder is committed. A value pasted or generated in chat can land there without anyone writing it. Before you stage a memsearch file, search it for the value with the compare rule below. If it matches, remove the line and tell the user. Before the first commit in a repo, check that `.memsearch/` and `.claude/` are ignored. Ignoring a folder does not untrack files already committed, so run `git ls-files .memsearch` as well, and `git rm --cached` any that are tracked, in the same commit as the `.gitignore` change.
- Tell two stored tokens or config values apart by hash, never by value. Pipe each one through `shasum -a 256 | cut -c1-12` and compare the short hashes. Hash each key field (app ID, API key) on both sides, so you can name which file matches which platform without printing any of them. To test a token against an API, pass it in an `Authorization` header from a variable set in that same command, print only the status code, and `unset` the variable.
- Never type a known secret literal into a search command. The command text lands in the transcript, and so does the value. To scan notes or memsearch files for a value, load it from its source first (`k=$(pbpaste)`, or the env var), grep with `"$k"`, and report only the match count. If a literal already went into a command, say so in one line and recommend rotating it if it is durable.
- Compare a value with a file without printing either. Run `k=$(pbpaste)` then `grep -qF "\"$k\"" FILE`, and report "matches" or "differs".
- Mask every quoted literal before you show a diff: pipe through `sed -E 's/"[^"]*"/"<str>"/g'`. A length floor or a character class leaks. A mask such as `[A-Za-z0-9+\/=]{12,}` skips any key with `!` or a short length, and the key prints in full.
- A grep for a key name prints the whole source line, value included. Mask every quoted literal on the hit: `grep -n PATTERN FILE | sed -E 's/"[^"]*"/"<str>"/g'`. The earlier mask only catches long literals, so a short key still leaks through a plain grep.
- That mask only catches quoted values. Tokens in config files, such as a NuGet.config source URL, are often unquoted. Unity `.unity`, `.prefab`, and `.asset` YAML is unquoted too, so a grep for an Inspector field such as `appToken` prints its value. Mask the value side with `sed -E 's/(: *)[^ ]{12,}$/\1<masked>/'`, or report only its hash. To compare two copies of a constant, extract the literal and hash it: `sed -nE 's/.*KEY = "([^"]*)".*/\1/p' FILE | tr -d '\n' | shasum -a 256 | cut -c1-12`. Before you `git diff`, `cat`, or `grep` a config file, run `git grep -nE 'ghp_|github_pat_'` first. Mask any hit with `sed -E 's/(ghp_|github_pat_)[A-Za-z0-9_]+/MASKED/g'`. If a secret already printed in chat, say so in one line and recommend rotating it.
- A secret in the working tree is not fixed until the file no longer holds it, and the change to that file is committed or deliberately kept out. Check the staged diff before a commit. A committed secret stays in history.
- A credential committed in a tracked config file, such as a package-feed token in a `NuGet.config`, stays in history even after a later commit removes it. Keep its diff out of every commit slice, name the file in the report, and recommend rotating the credential before any push. Mask the value when you show its diff.
- Find a committed secret with `git log --all -S 'VALUE'`, then `git grep -lF 'VALUE' SHA`, then `git branch -r --contains SHA`. Report the commit, the file, and the remote branches.
- Before you commit a folder of raw captures (logcat, DebugView, screen logs), scan it with counts only: `grep -rlcE 'PATTERN' DIR` prints file names and counts, never the matched text. Keep each pattern to plain literals. A SDK error line that names a key, such as "set by calling FacebookSdk.setClientToken", is text, not a value. Name the hit kind in the report, and stop only if a hit carries a value.
- Recommend rotating a secret that reached a pushed branch. Do not rewrite history or force-push unless the user explicitly asks. That breaks every other clone and cannot be undone. A rewrite also does not remove the exposure: the host can keep serving old commits by SHA, so rotation stays the fix.
- When the secret encrypts stored data, warn that a build with the new value cannot read data written with the old one. Ask whether an old build has reached players.

- Build-signing passwords (an Android keystore, for example) follow the same rule. Read them from environment variables first, then from a gitignored local JSON file. Commit only an example file with empty values, and add the local file to `.gitignore` in the same change.
- A keystore file is a secret even with no password in the path. Before a push or a merge into a release branch, run `git ls-files '*.keystore' '*.jks'` and check each hit against `.gitignore`. A tracked keystore that is not in `.gitignore` is a stop: report its first-add commit (`git log --diff-filter=A -- FILE`) and its remote branches, and recommend rotating the signing key if it is shared. Do not untrack or rewrite history without the user's yes.

- Sign-in for a CLI that needs a browser login (rclone, gcloud, and similar): never ask the user to paste a token, password, or auth code into chat. Give them one command to run with the `!` prefix, so the OAuth token lands in the tool's own config file. Output from a `!` command lands in the chat, and some sign-in commands print the token (`rclone config create` prints the whole config). Before you give the command, check whether it prints the token. If it does or you cannot tell, end it with `> /dev/null`. Tell the user to paste nothing back, and confirm the sign-in yourself with a read-only call. Promise that the token stays out of the chat only after you have checked.
- A sign-in that takes a typed secret (an S3 or MinIO access key, an API key) never goes on a command line. The `!` command's text reaches the chat, and the shell keeps history. Have the user run the tool's interactive prompt (`rclone config`) in their own Terminal app, not through `!`.

Generator details and the length rule: `scripts/key-to-clipboard.sh`.
