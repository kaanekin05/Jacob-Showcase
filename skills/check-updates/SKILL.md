# /check-updates

Read-only freshness sweep across every external thing Jacob depends on. **It reports; it never writes.** Applying an update is a separate, per-item, human-approved step (see [Apply](#apply) below). This exists because Jacob vendors, cherry-picks, and depends on upstream sources that drift silently, and there was no single pass that asked "what's stale?"

`update_policy` (set on every `skills.lock.json` entry) governs each skill:
- **track** — clean vendor, safe to re-pull → compared pin↔upstream.

## Reading the report

- **✓ up-to-date** — pin matches upstream HEAD. Nothing to do.
- **⬆ BEHIND** — upstream repo moved past the pin. Candidate for update (confirm the skill's own subfolder actually changed — `git ls-remote` sees repo-level HEAD, not the subpath).
- **⚑ review diff** (adapted) — upstream moved; requires a manual 3-way diff, never an overwrite.
- **~ no commit pin** — a `track` skill with no `source_commit` recorded; re-pull to compare, and record a commit pin while you're there so it becomes precisely trackable next time.
- **? unreachable** — repo/release not found (e.g. renamed org, deleted repo). Investigate provenance.

§performance reuses these glyphs with vault meanings: **~** there means "not in the registry" (self-distributed, so unauditable — not necessarily stale), and **⚑** means a duplicate plugin id rather than an adapted-skill diff.

## Apply

**This skill is the canonical owner of the refresh procedure** — `AGENTS.md` §invocation keeps only the headline and points here.

**Not automated. One item at a time, each ending in a `scripts/doctor.sh` run + a commit — and only when the user asks.** Per `AGENTS.md` §workspace (commit only when asked, and refresh once in Jacob — never via `/plugin`) and §behavior (approval gates).

Route on the entry's `update_policy` first (`track` → safe re-pull · `adapted` → 3-way diff, never overwrite · `frozen`/`native` → skip; semantics in `rules/Jacob_Layout.md` §layout/skill-inventory). Then:

**If the file set changed** — files added or removed, not just edited — **re-run `./scripts/bootstrap.sh`** before `scripts/doctor.sh`, so the symlink spine matches the new contents. Skipping this is how a re-vendored skill ends up half-wired.

- **track skill** → re-pull the folder from `source_url` at its branch → bump `version` / `files_hash` / `source_commit` / `updated_at` in `skills.lock.json` → `./scripts/doctor.sh` (must pass) → commit `chore: bump <skill> to <version>`.
- **adapted skill** → fetch upstream, diff against the vendored copy, **hand the user the diff** and let they choose what to port. Never clobber. After porting, bump `updated_at` (keep noting it's adapted) → `./scripts/doctor.sh` → commit.
- **plugin** → no plugin has a vendored copy in Jacob since 2026-10-01, so all five are plain Claude-managed plugins: update `superpowers`, `memsearch`, `csharp-lsp`, `unity` and `claude-obsidian` through Claude Code normally. If a vendored subset is ever reintroduced, refresh the vendored skill and do **not** route through `/plugin`/marketplace (§invocation).
- **pip package** → `pip install --upgrade <package>` → verify with `pip show <package>` → no `scripts/doctor.sh` run needed (pip packages aren't doctor-checked). To track a new package, add its name to the `PIP_PACKAGES` array in `check-updates.sh`.
- **Obsidian app or community plugin** → **there is no script apply path, and never should be.** Both are installed through Obsidian's own GUI, and the vault's `.obsidian/` is user data that the update procedure is explicitly forbidden to overwrite (`vault/MAINTENANCE.md` §Update). Hand the user the finding and the in-app step: app updates via Settings → General → Check for updates; plugin updates via Settings → Community plugins. A **REMOVED** plugin is the one worth escalating — it is no longer reviewed or served by the catalog, so it will not auto-update and may be unmaintained. A **duplicate id** is resolved by deleting the folder that is not enabled, which is a filesystem action inside user data: confirm the specific folder with the user first.

Model rosters have **no apply path** here — Claude model selection is manual and
user-owned, and neither this skill nor `scripts/doctor.sh` inspects it.
